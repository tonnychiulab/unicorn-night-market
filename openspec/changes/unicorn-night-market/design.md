# Design

## Context

空專案，尚無遊戲程式。行為見 `specs/stall-service`、`specs/unicorn-patron`、`specs/night-run`。動機見 proposal.md 的 Why。硬限制是單一可離線開啟的網頁，zip 後 ≤ 13,312 bytes，畫面與音效不得靠外部檔。

## Goals / Non-Goals

**Goals:**

- 三種小吃共用同一套「掃描標記 + 一次判定」操作，靠區間不同分出火候、臭度、油溫／完整度。
- 獨角獸、夜市燈光、蒸氣與彩虹勇氣都用 Canvas 2D 即時畫。
- 鍵盤（空白鍵或 Enter）與點擊／觸控都能端出。
- 用系統已安裝的繁體中文字型繪字，不把字型檔打進 zip。

**Non-Goals:**

- 多關卡地圖、道具商店、連線排行榜。
- 真實夜市名稱、品牌或照片。
- 為三種小吃各寫一套完全不同的迷你遊戲。
- 繪圖版（Seoul Market 迷你包與 CC0 小馬）不在本變更。見 `illustrated-edition`。本變更的 13KB 版維持程式繪圖。

## Decisions

### 單一 HTML，無框架、無執行期依賴

遊戲寫在 `index.html`：內嵌 CSS 與一段 script。不引入引擎或套件。另備一個只負責把 `index.html` 壓成 zip 的檢查方式，zip 本體不進遊玩路徑。

不做建置打包器。多一個工具鏈會吃掉除錯時間，13KB 內手寫比 minify 管線更可預期。若手寫超過限制，再考慮只壓 script 的極短步驟，而不是一開始上框架。

### 三種小吃是同一條掃描條的三種區間

畫面上有一條左右循環的標記。玩家按一次（或點一次）就端出，並依標記落點判定：

- 豬血糕：中間窄窗是剛好；左側太生，右側烤焦。
- 臭豆腐：中間是可接受臭度；左側太清淡，右側太臭。
- 炸皮蛋：中間是油溫剛好且蛋完整；左側油溫不夠，右側過晚所以破裂。

區間寬度與標記速度可在數值表裡調，不改操作。這樣三種失敗文案都成立，程式只留一組輸入與一組判定。

不做三種獨立手勢。規格要求的是可分辨的成敗原因，不是三套操作；獨立手勢會直接威脅 13KB。

### 狀態機：標題、做菜、結算、收攤

`title` → `cook` → `beat`（這一客成敗短暫停）→ 勇氣大於 0 則回 `cook`，否則 `over`。`over` 接受再來一局，分數歸零、勇氣回到滿值。分數只在成功時加。每一客進入 `cook` 時重設倒數。

勇氣用 0–100。成功 +15，太清淡或太生 −10，其餘失敗 −25，低於 0 就收攤。數字寫在同一張表，方便調手感而不改流程。

### 畫面與聲音都在程式裡生成

Canvas 固定邏輯解析度，再用 CSS 拉滿視窗。獨角獸用圓弧與三角形角畫；夜市用深色底、暖色燈條、油煙粒子（少數圓點）。彩虹勇氣是一排色塊。音效用 `AudioContext` 的短噪音與方波：下鍋、成功叮一聲、失敗下滑。第一次按鍵或點擊才建立 AudioContext，以避開自動播放限制。

不使用外部圖片、音檔或網路字型。系統字型堆疊：`"PingFang TC", "Microsoft JhengHei", sans-serif`。

### 文案維持短繁中

標題用「獨角獸夜市」。失敗原因只用規格裡的那幾句：太生、烤焦、太清淡、太臭、油溫不夠、皮蛋破了、逾時。避免長篇教學；標題畫面一行字說明「按空白鍵或點畫面，在標記進入區間時端出」。

## Risks / Trade-offs

- [三種小吃手感太像] → 區間位置、標記速度、顏色與失敗文案必須不同；實作時先用三組數字表分開調。
- [繁中字形把 zip 撐爆] → 只靠系統字型，不嵌入字型檔；若某環境缺字，退回 sans-serif，仍顯示字串。
- [13KB 不夠] → 先砍粒子與音效層數，保留三種判定、勇氣、分數與再來一局。
- [2026 已不能投稿] → 規格仍按賽制驗收，成品以本地可玩為準，不假報已送出。
- [觸控與鍵盤搶事件] → 同一函式處理 pointerup 與 keydown，並忽略重複按住。

## Migration Plan

從空目錄加入 `index.html` 即可遊玩。沒有舊資料要搬。若大小或手感不對，刪掉或改回該檔即回到上一版。不需要伺服器部署。

## Open Questions

無。檔名定為 `index.html`，數值（窗寬、速度、勇氣加減）留在實作時調整，不改變規格行為。
